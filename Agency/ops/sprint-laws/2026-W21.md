## RULES — binding on all 59 agents next Sprint forward

### Rule 21-1 — PATCH allowed-fields must include any new column before writing
**Why:** GAUGE scored 770 records correctly but persisted only 118 because `lead_score` wasn't in the PATCH allowed-fields whitelist at `tools/kingdom-reach/index.js:359`. Silent 400 "No valid fields" returned for the rest.
**How to apply:** Whenever a schema migration adds a column AND any agent will PATCH it via API, update the `allowed` array in the same commit. Failure mode is silent in current code — error doesn't throw.

### Rule 21-2 — Server.js whitelist required for token-auth-only endpoints
**Why:** `/variants/stats` returned 401 despite valid token because `tools/crm/server.js:593` has a blanket /api auth middleware that requires session — token-only access requires explicit path whitelist.
**How to apply:** Any new `/api/kingdom-reach/*` endpoint that needs token-only access (no session) MUST be added to the whitelist on line 593 of server.js. Otherwise the handler-level token check never executes.

### Rule 21-3 — Windows CLI guards use endsWith filename, not URL compare
**Why:** `import.meta.url === \`file://${argv1.replace(/\\\\/g, '/')}\`` produces a 2-slash URL on Windows while `import.meta.url` returns a 3-slash URL (`file:///C:/...` vs `file://C:/...`). CLI block never runs.
**How to apply:** Use `argv1.endsWith('<filename>.js')` instead of URL comparison. Cross-platform, simpler.

### Rule 21-4 — Fly.io rate limit is ~200 req/min — throttle long-running PATCH loops
**Why:** GAUGE's first throttle-less run got rate-limited after 118 PATCH calls. Subsequent calls returned "Too many requests".
**How to apply:** Any script that issues > 100 sequential CRM API calls MUST throttle. Standard pattern: 200ms inter-call gap + 5s breather every 50 records + 30s exponential backoff on 429 responses (see `tools/kingdom-reach/lead-score.js` lines 130-150 for reference implementation).

### Rule 21-5 — Hormozi 8-12% breakup reply window = measure at hour 48 from send
**Why:** Touch-3 fired 2026-05-27 16:51 EDT. Industry data says replies cluster within 48-72 hrs.
**How to apply:** Run `node tools/kingdom-reach/check-replies.mjs --since=2026-05-27` at 2026-05-29 17:00 EDT and again at 2026-05-30 17:00 EDT. Record actual reply rate vs Hormozi projection. If < 5%, GUARDIAN writes upgrade prompt to WORDSMITH for breakup_warm copy.

### Rule 21-6 — Auto-blog Gemini fallback chain requires `fallback-post.md` to exist
**Why:** 2026-05-25 blackout (all 3 contingencies triggered) was traceable to: Gemini quota hit + queue empty + … if `landing-page/content/blog/fallback-post.md` had been missing, the static fallback would also have failed. File is currently present (verified 8.8KB, last modified 2026-04-01).
**How to apply:** WITNESS scoreboard adds a daily check: `test -f landing-page/content/blog/fallback-post.md` — if missing, P0 to King.

### Rule 21-7 — Test records pollute production crons until filtered explicitly
**Why:** "Final Verify Test" zombie row in `ai_orders` triggered `cron-check-orders.mjs` every 24 hrs for ~24 days, spamming King's inbox with "Logo Review Overdue" alerts.
**How to apply:** All cron queries against shared production tables MUST filter `business_name NOT ILIKE '%test%'` AND `email != 'king@crownmediagroup.co'`. Fixed in commit `e38208a`.
